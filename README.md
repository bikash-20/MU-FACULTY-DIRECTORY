## About This Project

**MU ClassCraft** is a community-built, open-source Progressive Web App I developed independently to help students at Metropolitan University instantly find faculty contact details, departments, designations, and qualifications — without navigating clunky university portals.

This is a **real-world, production-deployed application** used by students daily. It is not a classroom assignment or tutorial project. Everything — design, data collection, architecture, PWA implementation — was researched, built, and maintained by me from scratch.

> *I built this because I believe every student deserves fast, easy access to the people who teach them. When I leave for higher studies, I hope this keeps serving the university community.*

## Getting Started

### View Locally

No build step. No npm. No framework. Just open the file:

```bash
git clone https://github.com/your-username/mu-classcraft.git
cd mu-classcraft

# Option 1 — Python (built-in)
python -m http.server 8000

# Option 2 — Node.js
npx serve .

# Then open http://localhost:8000
```

>  Service Workers require `localhost` or `https://` — opening `index.html` directly as a `file://` URL will register the SW but some features may behave differently.

### Deploy Your Own

1. Fork this repository
2. Connect to [Vercel](https://vercel.com)  Import Project
3. No build settings needed — it's a pure static site
4. Vercel provides HTTPS automatically 

```bash
# Push an update
git add .
git commit -m "feat: add new faculty data"
git push
# Vercel deploys in ~30 seconds. Users see the update toast automatically.
```

## Service Worker Architecture

```
Page Load
    │
    ├─ HTML document     Network-First  (always fresh when online)
    │                      └─ Cache fallback if offline
    │
    ├─ CDN assets        Stale-While-Revalidate
    │  (Bootstrap, Fonts)   └─ Serve cache instantly, update in background
    │
    ├─ Images            Cache-First    (long TTL, bandwidth-efficient)
    │
    └─ Local JS/CSS      Cache-First    (instant from cache)
```

**Update flow:**
```
You push to GitHub
     Vercel deploys (~30s)
     SW polls for update (every 60s or on page load)
     New SW downloads silently in background
     "New version ready — Refresh" toast appears
     User clicks Refresh  instant reload with new content
```

## Live Data Pipeline

Faculty data isn't hand-typed — it's pulled live from `metrouni.edu.bd` on demand:

```
scripts/scrape-faculty.mjs   (Node 18+, zero deps)
        │
        │  fetch + regex-parse each dept listing page
        ▼
   faculty.json    { generatedAt, source, count, faculty[] }
        │
        │  served by Vercel as a normal static asset
        ▼
   sw.js           networkFirstFaculty(request, CACHE_STATIC)
        │
        │  on change, postMessage to every client
        ▼
   index.html      re-fetches, re-renders, updates "Live · 30s ago" badge
```

**Three freshness guarantees:**

1. **Scraper freshness** — re-run `npm run scrape` weekly (or after the uni adds a new hire). The scraper preserves your existing email/phone/qualifications/specialization per person, so nothing is lost when the listing page changes shape.
2. **SW freshness** — `networkFirstFaculty()` always tries the network first. If the server's `generatedAt` (or payload length, if the header is missing) differs from the cached copy, the SW caches the new response and broadcasts `FACULTY_UPDATED` to every open client.
3. **UI freshness** — the hero shows a **"Live · updated 5m ago"** pill with a pulsing green dot. The label refreshes every 30 seconds and on `visibilitychange`. Clicking it forces a re-fetch without waiting for the SW poll.

The badge hides itself gracefully if `faculty.json` is missing a `generatedAt` field — old data still renders, just without the freshness claim.

## Extending the App

### Add / Refresh Faculty Data

Faculty data is **scraped live from [metrouni.edu.bd](https://metrouni.edu.bd)** and stored as JSON. You don't hand-edit it — run the scraper:

```bash
npm install            # no deps, but this initializes the project
npm run scrape         # scrape every department, write faculty.json
npm run scrape:cse     # scrape only CSE while iterating
npm run scrape:dry     # preview without writing faculty.json
```

The scraper:
- Walks all 8 departments (CSE, SWE, DS, EEE, BA, ECO, LJ, EN)
- Parses each faculty listing into `{ name, designation, department, profileUrl }`
- Splits multi-line designations (e.g. "Associate Professor / Head, Dept. of CSE")
- Detects "Dean, …" / "Head, …" / "Coordinator, …" prefixes and routes them to a `note` field
- **Preserves** the email, phone, qualifications, and specialization you already have on file for each person (matched by `name + department`)
- Sorts the output by department  designation rank (Professor  Lecturer  TA)  name
- Writes an envelope:

```json
{
  "generatedAt": "2025-01-15T10:42:00.000Z",
  "source":      "https://www.metrouni.edu.bd/sites/university/faculty-members",
  "count":       153,
  "faculty":     [ /* 153 records */ ]
}
```

If the university adds or removes someone, re-running `npm run scrape` regenerates `faculty.json` — the live SW broadcast in `sw.js` (network-first faculty strategy) then pushes the new dataset to every open client without a manual reload.

### Bump Cache Version on Deploy

```js
// sw.js — line 17
const CACHE_VERSION = 'v1.3.0';  //  increment on every deploy
```

## Tech Stack

This project intentionally uses **zero dependencies** beyond CDN-delivered UI libraries:

| Layer | Technology | Why |
|---|---|---|
| **Structure** | HTML5 / CSS3 / Vanilla JS | No build step, maximum portability |
| **UI Components** | Bootstrap 5.3 | Responsive grid + accessible components |
